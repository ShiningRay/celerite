## 2026-11-24：解析/安装计划缓存的六成分键与只读校验（M8 L165 P1，task-259）

### oracle

参考 Bundler 4.0.24 没有跨命令的解析/安装计划缓存：每次命令都在 Ruby 进程内重新求值 Gemfile、重算解析结果。因此本项不与参考行为作兼容声明；参考侧只继续约束命令 stdout/stderr、退出码、锁文件内容不变。P1 不接任何命令调用点，故这些行为天然不变。

### 参考锚点

- 设计依据 `docs/roadmap-evidence/M8-plan-cache-plan.md:58-115`：六成分键、canonical JSON、只读校验、损坏删除、格式 `celerite-plan-cache/1`、`<root>/plan/v1/<namespace16>/<sha256(key)>.json`、MAX_ENTRIES=256、MAX_BYTES=16 MiB。
- 首辅裁断（task-259）：设计 §7 的诊断与 V1「开关开启不改变 stdout/stderr」冲突，故诊断只在 `CELERITE_PLAN_CACHE_DEBUG=1` 打印；`CELERITE_PLAN_CACHE=1` 单独开启必须零输出变化。P1 不接 CLI。

### 实现位置

- `src/celerite/plan_cache.cr`：独立模块，`src/celerite.cr:32` require。无写 API、无 prune、无 CLI 调用点。
- 六成分 `sources` / `credential_namespace` / `checksums` / `platform` / `abi` / `build`；`key_for` 返回 canonical JSON 的小写 hex64 SHA-256；`build_key` 组装六成分；`components_for` 从既有 Definition/Lockfile/Config/Abi/本机平台取数，不起桥。
- GEM scheme/host 小写、剥 userinfo、去尾斜杠；PATH 绝对化并以 `/` 结尾；GIT URL + 小写 40-hex revision + submodules + glob；自定义 type 原样 + plugin_type。Credential namespace 只落 16 位 SHA-256；checksum 用 `Checksum.normalize_hex`；ABI 三字段必须 complete；build 参数按 `Config.key_for("build.<name>")` 读取、空白折叠、顺序敏感。
- `read(key)` 校验 format、文件名即 `sha256(key)`、嵌入 key 重算相等、嵌入 `credential_namespace` 等于当前 namespace、payload digest 相等；损坏一律删除条目并返回非 hit，不抛异常。诊断仅 debug 开关下走 stderr。

### 已声明差异

- 六成分键故意**不含** Gemfile 工程根、`BUNDLE_PATH` 或安装根：同一 HOME、同一锁/源/checksum/ABI/build 可得到同一 key。P1 不用于任何命令决策；P2 若复用命中条目，必须要求 payload 与项目根无关，或在复用前重查 project/install root，绝不盲目接受含绝对路径的 payload。
- `CELERITE_PLAN_CACHE=1` 单独开启零输出变化；只有额外设置 `CELERITE_PLAN_CACHE_DEBUG=1` 才向 stderr 打印状态/原因，且原因集为静态标签、不含凭据明文。
- 无写 API、无 prune、无 CLI 接线；MAX_ENTRIES 仅为 P2 裁剪预留常量，MAX_BYTES 在 P1 只用于单条目读取上限。损坏 JSON 的删除只针对本布局下的 `.json` 文件，删除失败不影响返回非 hit。无 HOME 且未设 `CELERITE_CACHE_DIR` 时路径不可用。
- 未验证：未在 Linux/macOS 或第二个 Ruby ABI 上实测键稳定性；未测多进程并发读写；未验证 P2 的写入器与真实命中行为。
