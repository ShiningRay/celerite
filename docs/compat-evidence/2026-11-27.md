## 2026-11-27：Ubuntu lock fast hot 的 platforms 根因定位（task-283 后续）

### oracle

- GitHub Actions run `45957802760` @ `b341647` 的 Ubuntu 两格 debug artifact；Windows 两格同源正门成功。

### 参考锚点

- `src/celerite/resolution.cr:2716-2733`：非 Windows/Java 的 generic-local=`ruby` 平台，在全新纯 Ruby 锁中同时加入本机平台与 `ruby`。
- `src/celerite/lock_fast_path.cr:150-152`：task-261 收紧后的门只接受 `[local_platform]`。

### 实现位置

- 失败路径仍是 `src/celerite/lock_fast_path.cr` 的平台精确匹配门；不是 plugin index、环境签名或证书字段。

### 证据

- artifact `lock-fast-hot-debug.stderr` 两行均为 `fast-path: lock miss (platforms)` 与 bridge stats；stdout 为 `Writing lockfile`。
- Windows 两格 success；Ubuntu 两格在 `Run fast-path CI gates` 的 lock fast hot 失败，后续 stats-off/capability/old-binary 未执行。
- Linux 规范锁形态为 `[x86_64-linux, ruby]`，而 Windows 为 `[x64-mingw-ucrt]`，所以 exact `[local]` 在 Linux 必然回落。

### 已声明差异

- 该现象是 task-261 为阻止新增平台后误命中而采取的保守门在 Linux 规范锁上的过窄回落，不是功能正确性差异。
- task-284 拟仅放行非 mingw/mswin/java 的有序 `[local, "ruby"]` 规范对；第三平台、其他顺序、Windows+ruby 继续回落。四格 CI 在该修复合入并实跑前仍不得宣称通过。
