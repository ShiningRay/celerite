## 2026-11-23：全量 `crystal spec` 的 Windows 前提，与 3 条残留红的归因

**oracle**：本节的判定基准是参考 `bundler-4.0.24` 在同一 fixture 上的输出与退出码，以及 Crystal spec 的 `Finished in` 汇总行；不含上游 spec 的断言。

**结论先行**：全量套件在 `1644b1f` 上跑到 `Finished in 36:19 minutes`、`1038 examples, 3 failures, 0 errors, 0 pending`。3 条红全部是**陈旧的 spec 期望或脆弱的断言**，不是产品缺陷——其中两条的期望与参考实现的实际行为相反。

### 环境前提（六条，缺任一条都会得到假红）

本仓在 Windows 上对临时目录的形态极其敏感，六条前提均由 A/B 对照逐条证实：

1. **原生 Windows 形态**：`TMPDIR`/`TMP`/`TEMP`/`HOME`/`USERPROFILE` 必须写 `C:/…`。写成 msys 形态 `/c/…` 时 `Dir.tempdir` 返回 `C:\c\…`（把 `/c` 当成相对路径再拼盘符），`spec/m7_list_groups_plain_env_spec.cr`、`spec/m7_plugin_conflicts_spec.cr`、`spec/m7_plugin_install_source_spec.cr` 随即报 `Unable to create directory … 拒绝访问`。
2. **落在被测 checkout 之内**：`C:/t/tmp`（8 字符）与 `C:/Users/ShiningRay/tse/tmp` 由 bash 与 `crystal eval` 都可写，但 `crystal spec` 里拉起的 `celerite.exe` 一律报 `Unable to create directory: 'C:\t\tmp\…': 拒绝访问。`；同一二进制改从 `C:\t` 启动即成功。即写权限取决于启动时的 cwd 是否在被测树内。
3. **真实路径，不能用 junction**：RubyGems 会把 junction 解析成真实路径，而 `src/celerite/resolution.cr:825` 用 `starts_with?` 字符串前缀比较 `ENV["GEM_HOME"]`，于是经 junction 拼出的 `GEM_HOME` 下所有已装 gem 被判为「不属于本项目」：`spec/m7_no_lockfile_commands_spec.cr`、`spec/m7_local_install_spec.cr`、`spec/m7_local_install_missing_dep_spec.cr` 报 `Could not find gem … in locally installed gems.` exit 7（同一批 17 examples：junction 根 5 failures，真实路径 1 failure）。这是产品侧真实的归一缺口，只在 symlink/junction 拼法下可见。
4. **`core.longpaths = true`**：本仓根已 47 字符，工作区内的临时根 72 字符，其下 git 对象路径越过 `MAX_PATH=260`，`spec/git_source_spec.cr` 报 `Filename too long` / `loose object … is corrupt`。
5. **不与并发会话共享同一 temp/home**：两个进程互删临时对象会造出假红（实测 11 failures 与 7 failures + 4 errors 两种形态）。
6. **临时根要短**：即使 1–5 全满足，72 字符的临时根仍会让 `spec/m7_binstubs_path_source_spec.cr`、`spec/m7_build_args_spec.cr`、`spec/m7_prefer_local_spec.cr`、`spec/m7_plugin_source_typed_spec.cr` 一族转红（同一 HEAD 实测 12 failures）；缩短到 30 字符后只剩 3 条。故全绿只能在**短路径 checkout** 上复现——本节的运行用的是 `git clone` 到 `C:/t/cel`（8 字符），临时根 `C:/t/cel/.tmp-scratch/se/tmp`（30 字符）。

**实现位置**：前提 3 的成因在 `src/celerite/resolution.cr:817-847`，其中 `home_prefix = home.gsub('\\', "/").chomp("/") + "/"` 与 `next unless gem_path.starts_with?(home_prefix)` 是纯字符串比较；该过滤器由 `1c0c214 feat(M7 task-5): honor --local and --prefer-local during install`（2026-11-15）引入。

### 3 条残留红的归因

1. **`spec/m7_build_args_spec.cr:97` / `:114`（2 examples）——期望与参考行为相反。**
   `code.should eq(0)`，实测 `got: 17`。fixture `spec/fixtures/build-args/` 只有 `build-args-demo.gemspec`、`ext/extconf.rb`、`gems/build-args-demo-1.0.0.gem`，**没有 `specs.4.8.gz`**；以 `source "file:///…/spec/fixtures/build-args"` 建项目后，紧凑索引不可用、回退 legacy 索引缺文件，两侧都失败。
   参考侧实测：`ruby -e 'gem "bundler","4.0.24"; load Gem.bin_path("bundler","bundle")' -- install` 在该项目上输出
   `Could not fetch specs from file:///C:/t/cel/spec/fixtures/build-args/ due to underlying error <Errno::ENOENT: No such file or directory @ rb_sysopen - C:/t/cel/spec/fixtures/build-args/specs.4.8.gz …>`，**`REF_EXIT=17`**。celerite 同样 exit 17 且措辞逐字对齐 → 两者一致，spec 的 `eq(0)` 已过时。
   该 spec 在 `a9b08c4` 上是绿的（`5 examples, 0 failures`），因为那时 celerite 吞掉了索引失败仍以 0 退出——与参考不忠实；`38aacfe fix(M7 task-137): report a GEM source index fetch failure as exit 17` 把行为矫正到与参考一致，spec 随之中断。
   建议修法（保留该 spec 的原意：验证 `build.<gem>` 参数透传）：给 `spec/fixtures/build-args/` 生成 `specs.4.8.gz` / `latest_specs.4.8.gz` / `prerelease_specs.4.8.gz`（仓内已有 `script/synthetic-index.rb` 可复用），而不是把期望改成 17——改成 17 会让这两例不再验证参数透传。

2. **`spec/m7_remove_failure_modes_spec.cr:91`——断言跨越折行边界。**
   断言 `err.should contain("so it could not be removed.")`，实测 stderr 为
   ```
   `nosuchgem` is not specified in
   C:/t/cel/.tmp-scratch/se/tmp/celerite-spec-…/Gemfile so
   it could not be removed.
   ```

   `word_wrap`（`src/celerite/cli/commands.cr:1180`，仿 Thor `word_wrap`，宽度取 `CLI.terminal_width`，默认 80）在 `so` 后折断，于是该短语跨行、不再是连续子串。
   参考侧同一项目的输出与之逐字相同（三档路径长度手工对照，只有换行位置随路径长度移动），故属断言脆弱：断言应改成不含折行位置的片段（如 `could not be removed.`）或先归一化空白。

### 已声明差异与不受影响的部分

- 上述前提不影响 Linux/macOS：1、2、6 是 Windows 路径形态与 MAX_PATH 造成，4 是 git 的 Windows 长路径开关。
- 前提 3 揭示的 `GEM_HOME` 前缀比较缺口**不是本次新增**，`a9b08c4` 上同形（`17 examples, 5 failures`），且只在 symlink/junction 拼法下可见；真正的修法是两侧都取 `File.real_path` 后比较，需另立任务。
- 短路径 checkout 的完整运行日志留在工作区外（`C:/t/cel/.tmp-scratch/spec-short.log`），不入库；本节记录的是可复核的命令与环境变量组合。
