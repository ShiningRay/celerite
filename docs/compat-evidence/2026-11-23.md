### 已声明差异

1. 2.7.2 profile 与 4.0.24 文案不同（建议名不带引号；大小写分支不打建议行），两夹具以 `deferred-2.7.2` 只钉 4.0.24；celerite 与 4.0.24 逐字一致。这与 task-141 的 `gem-did-you-mean` 同因，非 celerite 缺陷。
2. `outdated`（`src/celerite/cli/commands_surface.cr` 的 outdated 分支）刻意保持单行无建议，本轮未验证未改（参考 `cli/outdated.rb:35-39` 亦然）。
3. `info`/`show <name>`（`src/celerite/cli/commands_surface.cr:2234`）与 binstubs（`src/celerite/cli/commands_install.cr:2135`）两条建议接线未纳入本任务夹具，未验证。
4. 多建议项（`Did you mean 'a', 'b' or 'c'?`）在 `update` / `pristine` 上未单独取参考 oracle；仅 `lock --update` 路径有逐字 oracle（task-141），本轮 `update`/`pristine` 只实测单项与大小写两类。
5. 所有结论取自本机 Windows + `C:/Ruby40-x64` 的 bundler 4.0.24 与 2.7.2 profile，未在其他 Ruby 安装或真实 HTTP 索引上验证。
6. 差分夹具的 `stderr-contains` 走 N10（contains-only）语义，非整段 stderr 逐字比对；逐字比对由 spec 的 `eq` 承担。
